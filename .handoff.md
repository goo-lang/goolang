## What landed

### PR #255 — one escape engine, and the hole it made visible

`param_escape`, `block_escape` and `local_escape` ran three hand-maintained
copies of the same walk. The divergence was MEASURED before anything moved:
`walk_stmt` is ~200 lines in each, and `param` differed by ONE line (the return
signal) while `local` differed only by which bind function it called, at five
sites. `expr_taint` differed only by block's three source arms. `handle_go_call`
and the taint-set helpers were byte-identical in all three.

The whole difference is **six hooks**. `src/types/escape_core.{c,h}` is the
engine. 3,434 lines -> 2,497 including the new header.

**Proven live, not assumed:** deleting the `AST_POSTFIX_EXPR` arm from the
SHARED core reproduces the original defect (local-escape row 4 FAILS). That
same mutation left `param` and `block` green — **so neither of those 51 rows
covers `i++`.** That gap is real and still open.

Then, in one nine-line arm rather than three mirrored edits:

**A MAP KEY IS AN UNTRACKED REFERENCE.** `assign_to_lvalue` marked only the
RIGHT-hand taint, so the index of a non-identifier lvalue was never tainted.
Measured: in `m[f] = 1; return m` the map ESCAPED and `f` did NOT, yet
`goo_map_set_sv` keeps the key pointer verbatim and never frees it. A release
consumer would free a buffer a live returned map still holds. Sink #2b marks
the INDEX only, never the base. Rows 15 and 16, where 16 is the slice contrast
that was already sound because `append` is an ordinary call.

**The extraction paid for itself within one commit.**

### PR #256 — summarise the C shims, and unblock 30% of the daemon

T0's dominant finding: a C shim has no Goo body, so `param_escape_lookup`
misses and `call_taint` takes its pure-conservative branch. **Every local passed
to any stdlib call was marked escaping for that reason alone.**

The mechanism already existed with the right meaning — `goo_callee_is_non_retaining`'s
`whitelisted` branch skips the argument mark AND empties the result taint. It
was hardcoded to six `fmt` selectors. This is one new column on the shim
signature table, and those six `fmt` entries moved into it unchanged.

**NO separate `returns_borrowed` flag.** The plan asked for two facts and one
bit carries both, because the consumer already treats them as one.
`errors.Unwrap` proves the shape is right: it retains nothing but returns
`e->cause`, a pointer INTO its argument. A retention-only flag would have
marked it safe.

Every `1` is justified against the runtime C body beside its row. Unaudited
stays `0`: `os.*`, `far.*`, `fmt.Errorf` (%w retains), `fmt.Fprint*` (the writer
is an `io.Writer`, so a USER `Write` can store what it is handed).

Answering by package name needed a guard: a local named `strings` would
otherwise collect the package's whitelist. `selector_base_is_local` uses the
walk's own `LocalEnv`. That closes the same pre-existing hole for `fmt`.

**Measured on the real daemon:** `fields` and `err` flipped to non-escaping —
**30.2% of retained bytes**. `f` correctly stays escaping because the map holds
it as a key.

**Still inert for arenas, live only for locals.** No shim takes a user pointer,
so no arena value can reach a whitelisted call.

### PR #257 — a string literal is a real ARC object

A literal was the **FOURTH headerless pointer kind, and the only one nothing
excluded**. `codegen_const_string_value` emitted a bare byte array, so a release
would compute `global - 16` and hand .rodata to `free()`. NULL and
`goo_zerobase` are checked; an arena pointer has a static proof; a literal had
nothing. `last := ""` at `bench/daemon/daemon.goo:47` is that shape.

The global now carries a header with `GOO_RC_IMMORTAL` (`UINT64_MAX`), and
retain/release/free are no-ops on it. **UINT64_MAX not 0**, because 0 already
means "not a counted object" and reusing it would make `goo_release`'s underflow
panic unreachable.

Two gates, because neither half proves the other: `obj_header_test` row 15
tests the runtime (fails with "free(): invalid size" + core dump when the guard
goes), and `string-literal-header-probe` tests codegen's IR (fails when the
sentinel is wrong). The probe also runs `opt -passes=verify`.

## NEXT — T4, scoped and DECIDED, not started

**Emit `goo_release` for owned, non-escaping ERROR locals at function exit.**
User-selected scope this session: shallow (outer object only), error locals
first.

Why errors and not strings: T0+T3 re-measured the daemon and the string local
`f` still correctly escapes (the map holds it). The release candidates are
`fields` (a `[]string`) and `err` (an `error`). `err` is the smaller: a plain
pointer, one owner, no container.

| Candidate | Outer object | Inner it does NOT reach |
|---|---|---|
| `err` | 80 B/req, 5.8% | its message copy, 90 B, 6.5% |
| `fields` | 128 B/req, 9.3% | its 6 element strings, 118 B, 8.6% |

So a shallow release reclaims ~5.8% first, ~15.1% with slices. The full 30.2%
needs TRANSITIVE release, which is a separate and larger design.

**Three conditions must all hold before emitting a release:**
1. `local_escape` says the value does not outlive the function.
2. The local OWNS the value (not a borrowed view).
3. The binding site is NOT arena-routed.

**Condition 3 is a soundness rule, not a tidy-up.** Inside `arena { }` a local
can hold an arena pointer, which has no header. `local_escape`'s boundary is the
FUNCTION, so such a local reads as non-escaping and a release would free an
interior pointer. The coexistence spec covers PARAMETERS only. For the first
cut, skip every local declared inside an `arena { }` block.

**And a fourth question T4 must answer before it emits anything: do releases run
BEFORE or AFTER a function's deferred calls?** If before, a deferred call reading
the local dangles. This is why `local_escape` still carries
`defer_is_like_go = true` (see below).
