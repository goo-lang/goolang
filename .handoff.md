## Start here

**Phase 1a: closure environments become an allocation site.** Planned in
detail, and now UNBLOCKED — until PR #240 the construct did not even compile.
Three edits that only work together:

1. `discover_expr`'s `AST_FUNC_LIT` case (`block_escape.c` ~line 253) registers
   the `FuncLitNode` as a site **when `captured_count > 0`**. A non-capturing
   literal allocates no environment, so a site there would have nothing behind
   it.
2. `expr_taint`'s `AST_FUNC_LIT` case (~line 797) sets the environment's
   self-bit **AFTER** its `mark_escapes` call, never before. Before, and the
   environment is marked escaping at its own definition and the change does
   nothing. Sink #3 (capturing a value escapes that value) is NOT relaxed by
   this arc.
3. `function_codegen.c` ~line 955 passes `(ASTNode*)lit` instead of `NULL`.
   `lit` is already in scope. This is the ONLY codegen site in scope — `:436`
   and `:450` are promoted per-variable slots, a different kind.

## The memory model, in numbers

All reproducible from `docs/adr/0002-measurements/` (its README re-runs them).

- **The daemon shape retains ~1.63 KB per request, forever.** 82.6 / 163.7 /
  325.5 / 651.2 MB at 50k / 100k / 200k / 400k requests, against Go's flat
  ~8 MB on the identical program. Exactly linear. At 1000 req/s that is 8 GB
  in ~80 minutes.
- **The opt-in `arena` does NOT rescue it.** 651,172 KB with it against
  651,164 KB without.
- **Why:** arenas reclaim ONLY the sites codegen emits directly in the block
  (`new`, `&T{}`) that `block_escape` proves non-escaping. `new`/`&T{}`
  measures 1.7 MB against 26.8 MB. `[]int{}` + `append` measures 14.2 MB
  against 13.7 MB. Every allocation through a runtime helper — append,
  slice/map literals, string ops, and EVERY stdlib call — is untouched.
- **The numeric hot path does NOT allocate per iteration**, so a per-object
  runtime cost cannot touch Goo's differentiator. That is the single most
  load-bearing measurement in the decision.
- **PHASE 1 WILL NOT MOVE THE 651 MB.** That lives in append and stdlib
  allocations which never reach `codegen_emit_alloc` — phase 2. Phase 1 makes
  `arena` honest for what it already claims. Say so, rather than letting the
  number imply otherwise.

## Traps found this session, each of which produced code that COMPILED

Every one is a defect a green suite could not find:

1. **A shim-table edit silently disabled a checker diagnostic.** The
   selector-call block in `type_check_call_expr` is gated on
   `!skip_variadic_builtin`. Giving the `fmt.Fprint` rows ZERO fixed params
   (necessary — `ShimParamKind` cannot spell an interface) moved them into
   exactly that skip class, so the writer check stopped running and the
   failure became backend noise. The golden-reject fixture caught it.
   **Before moving a check into that block, confirm the callee is not
   variadic-with-no-params.**
2. **A nil error is `{ i1 true, ptr null }`, NOT a zeroed struct.** The `i1`
   marks the slot valid. The NULL POINTER is what means nil. `LLVMConstNull`
   of the pair compiles, runs, and compares as NON-nil. Read the IR a real
   `func f() (int, error)` emits before hand-building any error value.
3. **Unwrapping a pointer before classifying a type over-accepts.** Removing
   the embedded-interface rejection also legalised `struct { *I }`, which Go
   rejects. Caught in self-review, by no gate.
4. **The arena stack was ambient state that func-lit codegen did not save**,
   so a closure's `return` freed the enclosing function's arena (PR #240).
5. **`make verify-core > log; echo $?` reports the ECHO's status.** A failing
   gate looked green. Capture the real status INSIDE the log:
   `{ make verify-core; echo "EXIT=$?"; } > log 2>&1`.

## Method notes worth reusing

- **Spike before implementing paid twice.** PR #233 stopped an interface-box
  implementation that would have failed, and step 0 of the arena work found
  two pre-existing defects INSTEAD of building on them. Both times the
  deliverable was a findings document, and both times it changed the plan.
- **Escape analysis cannot be validated by a green suite.** Over-marking is
  invisible, because it only costs memory. Under-marking is invisible until it
  corrupts. Every new site kind needs a measurable non-escaping case AND an
  escaping case per sink that READS the value after the block ends.
- **Verify a fixture RED before trusting it.** PR #240's rows 19 and 20 were
  proven RED by reverting the fix and rebuilding. Row 21 is an over-marking
  guard that passes both before and after.
- `go1.26.1` is at `/usr/local/go/bin/go`. Expected output for a golden
  fixture comes from `go run`, never hand-written.
