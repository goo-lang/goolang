## ANSWERED — ARC and `arena { }` can coexist, and ARC is unblocked

**Yes, via callee-side elision from the 7a summaries.** Full argument:
`docs/superpowers/specs/2026-07-28-arc-arena-coexistence.md`.

`block_escape`'s `call_taint` already routes a site to the heap whenever the
callee's summary says that argument is retained. So **an arena pointer can only
ever bind to a parameter proven non-escaping.** If ARC emits no retain or
release for such a parameter, a callee never releases a pointer that could be
arena-allocated. Caller and callee elide from the SAME summary and never meet.
The callee does not need to know where the value came from.

The audit's "flag bit in the header" option is worse than it recorded: an arena
object has NO header, so a release would read `ptr - HDR` inside the previous
object and then `free` an interior pointer. Making it work costs 16 bytes per
arena object plus a branch per release. Option 2 costs nothing.

**Answering it exposed a live use-after-free, now fixed.** A method call did not
mark its RECEIVER — a selector callee resolves to no summary, and a receiver is
not in `call->args`. `p.m()` inside an arena block left `p` arena-eligible even
when `m` stored it. Measured: printed garbage, **exit 0**, valgrind invalid
read. The same hole `handle_go_call` closed for `go p.m()`, left open on the
ordinary path, in BOTH sibling modules. Fix: mark the callee taint for the
non-identifier shape only.

**The RETURN boundary is answered too** —
`docs/superpowers/specs/2026-07-28-arc-return-convention.md`. Recommendation:
**owned (+1), with a uniform ABI**, and escape analysis removing the traffic it
can prove. The decisive argument is not cost, it is reversibility: a uniform ABI
that misses a summary costs one retain and one release, while a
summary-dependent ABI that misses one picks the WRONG convention and
double-frees. That is the receiver bug's failure mode promoted to the ABI.

The return boundary was audited, not assumed. The shape that could have slipped
is a NAMED result with a bare `return`, where `ReturnStmtNode->values` is empty
and the return sink never fires. It is sound, but by a different sink:
`LocalEnv` is seeded from `param_names` only, so a named result is not a local
and `p = q` is a store-escape. **Register named results as locals and the only
sink covering that shape disappears.** Pinned by `param_escape` row 20 and
`arena_named_result_probe`.

**Map-held references are answered too** —
`docs/superpowers/specs/2026-07-28-arc-map-held-references.md`. Recommendation:
**tag the map with a value kind and let the RUNTIME retain and release**, shipped
retain-first. `GooMapSV` already carries `key_kind` and `key_eq`, so a map
already holds type metadata and the precedent exists.

Emitting retain/release from codegen instead is disqualified by ONE fact:
codegen cannot enumerate a map's live keys, so it can never free a map at all.
A design that cannot free a map cannot fix the daemon shape, which is why
ADR 0002 exists.

Ship the retain before the release. A missing retain is a use-after-free, a
missing release is a leak — the same asymmetry the escape analysis already
uses. **Retain the NEW value before releasing the OLD**, or `m[k] = m[k]` frees
what it is about to store.

No live defect here: `m[k] = p` is already an unconditional sink
(`block_escape.c:599`), so an arena pointer stored into a surviving map is
heap-allocated. Measured, and now gated by `arena_map_store_probe`.

## IMPLEMENTATION STARTED — the object header is in, and invisible

`goo_alloc` carries a 16-byte header (`GOO_OBJ_HEADER_SIZE`), and
`goo_retain` / `goo_release` / `goo_obj_refcount` exist. **Nothing emits them
yet.** Gated by `obj-header-test` (11 rows, 25 checks) in verify-core.

Proven invisible: goldens **491/491** at -O0 AND -O2, arena probes 16/16
valgrind-clean, `alloc-doors-probe` PASS.

**The cost is real and paid in advance.** 16 bytes per allocation, buying
nothing until the release side lands:

| daemon | before | with header | delta |
|---|---|---|---|
| 50,000 requests | 82.6 MB | 92.7 MB | +12.2% |
| 400,000 requests | 651.2 MB | 733.9 MB | +12.7% |

**The parameter boundary is specified and costs ZERO instructions** —
`docs/superpowers/specs/2026-07-28-arc-parameter-boundary.md`. Every parameter
is borrowed (+0), UNIFORMLY, never summary-driven. That refines the coexistence
answer and strengthens it: no callee ever releases a parameter, so an arena
pointer passed anywhere is never released by the callee, with no appeal to the
summary. The summary stays load-bearing for ARENA routing, so the PR #248
receiver fix is still a real defect fixed, not made moot.

Three consequences DO emit, each its own increment:
1. `go f(p)` transfers +1 — the one exception, because a goroutine outlives the
   caller frame. `handle_go_call` already marks every `go` argument.
2. Returning a borrowed value needs a retain, per the owned-return convention.
   `return_escapes` is exactly that signal.
3. Storing a parameter retains at the store.

**NEXT INCREMENT — the first one that changes observable behaviour:**
scope-exit release of an owned local that provably does not escape. It is the
smallest change that makes a Goo program free something it does not free today,
and `bench/daemon` is the instrument. Everything before it is cost with no
benefit.

Then: slices of pointers (undecided — `goo_slice_append` copies raw bytes, so
nobody counts an appended pointer), atomic against per-goroutine counts (which
stops being theoretical the moment `go` transfers +1), and cycles.

## The position, now measured rather than assumed — ADR 0003, ACCEPTED

Before this session nothing in the repository had ever measured Rust. The goal
named a competitor nobody had run. `scripts/rust_compare_bench.sh` and `bench/`
close that, five programs in three languages, and every row asserts the
languages print the SAME output before any timing is reported.

| Benchmark | Goo | Go | Rust | Rust+SIMD |
|---|---|---|---|---|
| scalar, wall | **0.86 s** | 1.07 s | **0.86 s** | — |
| daemon, wall | 2.24 s | 0.79 s | **0.55 s** | — |
| daemon, peak RSS | **1,627 MB** | 7.0 MB | **1.95 MB** | — |
| stencil, wall | 0.27 s | 0.29 s | 0.16 s | **0.10 s** |
| text, wall | 1.43 s | 0.50 s | **0.31 s** | — |
| text, peak RSS | **768 MB** | 6.7 MB | **1.95 MB** | — |
| hello, compile | **0.05 s** | 0.11 s | 0.07 s | — |
| hello, binary | **92 KB** | 2,343 KB | 4,237 KB | — |

**Three working assumptions did not survive.**

- **"Goo wins parallel throughput" — false.** The 7.55x came from
  `stencil-parallel-probe`, which is Goo-8-lane against GOO-SERIAL, a
  self-comparison. Against Rust: rayon is 1.7x faster, rayon+SIMD 2.7x. Against
  Go it is a TIE, not the 1.3x win an unpinned run suggested. **Never say "Goo
  beats Rust at numerics."** Say "lanes scale 7.55x against serial Goo."
- **"Compile speed probably winning" — true, for the wrong reason, now FIXED.**
  See below.
- **"Reach parity on memory" — the gap is far worse than recorded**, because
  ADR 0002 measured against Go and Rust is tighter. 834x on the daemon, and
  4.1x slower in wall clock on the same program.

Established wins: **binary size** (25x Go, 46x Rust), **compile speed**,
**scalar parity with Rust plus a 1.24x win over Go**, and the parallel-safety
PROOF (compile-time disjointness, zero annotations — that claim is about the
proof, never about the throughput).

## Traps found this session, each of which produced code that RAN

1. **A 1.5x "regression" that was pure noise.** An 0.08 s benchmark is eight
   ticks at `/usr/bin/time`'s 10 ms resolution, and an unpinned process on a
   32-core box migrates between turbo states. Goo's samples came out bimodal;
   the median of a bimodal sample read as a clean 1.5x. Pinned, with a 10x
   workload, it is exact parity. **The harness now pins cores and sizes every
   workload past half a second, and its header says why. Do not remove either
   rule.**
2. **`goo --emit-llvm` emitted INVALID IR that `opt` could not parse.** A
   multi-value return never width-coerced a plain number, so `return 'A', 0`
   from a `(rune, int)` function emitted `ret { i32, i64 } { i64 65, i64 0 }`.
   `goostd/utf8` has exactly that shape, so EVERY program importing `strings`
   carried it. At -O2 the backend aborted with "Cannot emit physreg copy
   instruction" on some shapes and tolerated others. **No probe asked "is the
   emitted IR valid" — that is why it survived. Run `opt -passes=verify` over
   `--emit-llvm` output when touching codegen.**
3. **A slice entered the heap by one door and was resized by another.**
   `goo_slice_alloc` used raw `calloc`; `goo_slice_append` grew it with
   `goo_realloc`. Harmless while both are bare libc calls, heap corruption the
   moment a header exists. Gated now by `alloc-doors-probe`.
4. **Imported-package functions had EXTERNAL linkage**, so `globaldce` could
   not remove them. A hello-world calling `strings.Repeat` once dragged all of
   `goostd/strings` and `goostd/utf8` through -O2 and into the object — 30
   functions. Internal linkage: compile 0.23 s -> 0.05 s, stencil binary 534 KB
   -> 108 KB. **No package build cache was needed; that recommendation was
   withdrawn.**
5. **A comparison of two EMPTY files reported "IDENTICAL".** The symbol pattern
   missed the monomorphised name `StencilStep__n1`. The conclusion survived
   re-testing, but the evidence at that moment was vacuous. **Check that an
   extraction produced rows before trusting a diff of it.**

## Method notes worth reusing

- **A fix to one path of a shared shape must be swept across every path of it.**
  `handle_go_call` fixed "discarded callee taint" for `go p.m()` and wrote a
  nine-line comment explaining the hole. The IDENTICAL hole sat in the ordinary
  call path of the same two files and survived, because the fix was applied
  where the bug was reported rather than everywhere the shape occurred. Grep for
  the shape, not the symptom.
- **Prove a new gate can fail.** The receiver probe was re-run with the two
  source fixes stashed, and only then trusted. A probe nobody has seen fail is
  a probe nobody has tested.

- **Measure before asserting, and pin the cores.** Two published findings were
  wrong this session and both were measurement artefacts, not compiler
  defects.
- **Spike before implementing paid a third time.** The phase-2 spike found the
  phase was probably unnecessary; the ARC audit found a live heap bug. Both
  deliverables were documents, and both changed the plan.
- **Run other people's tools over your output.** The invalid-IR bug was found
  by pointing `opt` at `--emit-llvm`, not by any test.
- **Prefer a call to the existing owner over new logic.** Both codegen fixes
  this session were one call to a helper whose doc comment already listed the
  sites that had re-broken the same rule inline.
- The STE check is a HARD gate before `git push` — on PR #242 it exited
  non-zero and the push ran anyway. Check `$?` explicitly.
- `go1.26.1` at `/usr/local/go/bin/go`, `rustc` 1.96.0 stable AND nightly.
  Expected golden output comes from `go run`, never hand-written.
