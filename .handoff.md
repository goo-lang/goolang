## The design, for whoever picks this up

**Four conditions, all of which must hold** (`include/release_decision.h`):

1. `local_escape` says the value does not outlive the function.
2. The local OWNS the value, decided at the BINDING SITE.
3. Not declared inside `arena { }` (an arena pointer has no header).
4. Bound ONCE at function scope — not in a loop, and not re-assigned.

**The soundness direction is INVERTED from the escape passes.** There
`escapes = true` is safe. Here `release = false` is safe, so every unrecognised
path refuses and records WHY. `ReleaseVerdict` carries the cause, and every row
asserts the cause rather than a bare boolean.

**Condition 2 is a binding-site table, NOT ADR 0004's origin-emptiness.** That
proposal is constant-false: `local_escape`'s slots ARE local indices and a local
keeps its own bit for life, so no local's taint is ever empty. Measured in #259.
The working rule: `new(T)`/`&T{}` and composite literals are owned, a Goo call is
owned iff its callee's `return_escapes` is false, a shim call iff `non_retaining`
is 1, and a slice/index/selector or bare identifier is NOT owned.

**`ArcReleaseSite.field` says WHICH part of a slot is the object.** `-1` is the
slot's contents (a bare pointer, and a map, whose LLVM form is already `i8*`).
`0` is a fat value's buffer, and only `TYPE_SLICE` uses it.
**`TYPE_INTERFACE` is `{ vtable*, data* }` — field 0 there is the VTABLE, so there
is no general "release field 0" rule and never can be.**

**Ordering is STRUCTURAL.** `codegen_emit_deferred_calls` is a wrapper that runs
defers then releases, because a Go defer runs before the return and can read a
local through a closure. The 8 exit paths cannot drift.

**The release list is captured at DECLARATION time**, in `vscope_add`. Reading the
value table at exit emitted NOTHING — the function body is a block statement, so
`vscope_exit` truncates its locals first.

**`GOO_ARC_RELEASE=0` is the kill switch.** It leaves the plan NULL and emits
nothing. Every probe and `arena_rss_probe.sh` uses it as the control.

## NEXT, in the order I would take it

Shares are of the **952,000 bytes** left per 2,000 requests, re-measured after
#275. Group by REMEDY, not by allocation site — the totals reconcile exactly,
and the three records below account for 100.0% with nothing left over.

1. **The return-value construction, 350,000 (36.8%).** `concat`, `Itoa`,
   `Join`. The FINAL string genuinely escapes, but a chain of four concats
   leaves three dead intermediates. Nobody has costed the intermediates alone.
   Largest by raw bytes, but spread across SEVEN small records (36,000 / 38,000
   / 40,000 / 42,000 / 44,000 / 70,000 / 80,000), so it is seven fixes or one
   general one — and which of those it is has not been established.
2. **The `strconv.Atoi` error objects, 340,000 (35.7%).** Biggest single
   record, and the one with no cheap route. `err` is loop-scoped, so condition 4
   refuses it. Needs release at ITERATION end across the normal, `continue`,
   `break` and `return` paths — the ADR 0004 kill rule / CFG problem. The record
   is 160,000 DIRECT plus 180,000 INDIRECT, so read both or it looks half the
   size.
3. **The `strings.TrimSpace` locals, 262,000 (27.5%) — ONE record, TWO fixes.**
   `f := strings.TrimSpace(fields[i])`, loop-scoped. It splits by branch, and
   the split is why stage B is not worth the whole record:
   - ~180,000 (18.9%) is **STAGE B**, the `counts[f]` branch, where a map could
     take the key. Five of the daemon's seven fields take it.
   - ~82,000 (8.6%) is the `counts[strings.ToUpper(f)]` branch, where `f` is
     dead after the call and the map never sees it. That half needs the SAME
     loop-scope kill rule as item 2, not key ownership.
   The 14.7% in the previous handoff was this ~180,000 measured against the old
   1,225,982 denominator. The bytes did not move — the denominator did.
4. **STAGE B — a map takes a key from a LOCAL. STILL DEMOTED, and measured
   why.** Worth the ~180,000 identified in item 3, and it is the most entangled
   item on this list. It
   was planned as "stage A but riskier". It is not:
   - `f` escapes for TWO independent reasons. The RHS read `counts[f]`
     propagates f's taint through the `AST_INDEX_EXPR` arm, AND the write
     subscript sink marks it. MEASURED by dropping the index union from the read
     arm: local row 22 flips true->false while row 15 holds.
   - So it needs the over-conservative READ arm relaxed FIRST — a shared-engine
     precision change that reclaims ZERO bytes on its own and re-runs both arm

   - Then it still needs "is this map the local's only escape", and
     `local_escape` returns ONE BOOLEAN PER LOCAL with no site information at
     all. That guard cannot be expressed today.
   Do items 1 and 2 before this. Item 3's OTHER half rides on item 2's kill
   rule, so item 2 may shrink item 3 without anyone touching a map.
