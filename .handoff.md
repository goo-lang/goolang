## The question this session answered

"Is Goo ready to build testable, scalable, correct applications?" The
evidence-based answer, and it is worth keeping because it is not one question:

- **Correct — yes, for the subset it covers.** The gate net is unusually strong
  for a project this age, and nothing is advertised without a probe.
- **Testable — yes, as of this session.** `goo test` shipped, and a
  `package main` program can now be tested too.
- **Scalable — SPLIT, and the split is sharp.** Parallel compute is genuinely
  strong (MT scheduler, SPMD lanes, real cross-process NNG transport). Long-
  running services are impossible: v1 has NO systematic reclamation.
  `scripts/arena_rss_probe.sh` measures ~810MB vs ~14MB when an arena is
  removed, so anything allocated outside an arena is never freed. A daemon
  grows unbounded.
- **Applications — the blocker is the STDLIB, not the compiler.** Absent: `io`,
  `net`, `encoding/json`, `context`, `bufio`, `regexp`, `reflect`. No sockets,
  no HTTP, no JSON, no cancellation.

**CLI tools were chosen as the first target**, because a CLI process exits, so
the absence of reclamation does not matter. That target is now unblocked.

**Start here next session,** in this order:

1. **`errors.Is`** — fully spec'd by the spike below, four touch points, no open

2. **`os.ReadDir` + a `filepath` package** — the remaining CLI gap. A tool that

googrep now builds, runs correctly in a pipeline, tests, and carries NO

| Gap | What | Closed by |
|---|---|---|

| 2 | No program could write to stderr | #231, `fmt.Fprint*` + `os.Stdout`/`os.Stderr` |

**GAP 4 was the important one, and it falsified a handoff claim.** This file
used to say `call_codegen.c`'s argument handling "should now be considered DONE
as a drift source — there is no fourth loop left to find there." There WAS a
fourth loop: the vendored-package path passed each argument's raw `llvm_value`
on the stated assumption that "codegen_generate_expression loads scalar lvalues
to a value". That holds for a scalar and fails otherwise — a slice element
arrived as the GEP address, and a concrete passed to an INTERFACE parameter
arrived unboxed. All four loops now route through
`codegen_emit_fixed_call_arg`.

**`sort.Sort` could not be called from another package AT ALL**, and `sort`
shipped that way in #229 the same day. Its own tests missed it because an
internal test calls `Sort(s)` as a PLAIN call, never through the package path.
**An internal test does not exercise the import path** — worth remembering for
every future goostd package.

**GAP 2's writer is a file descriptor, and that is safe only because of the
guard.** No `io.Writer` exists, so the shim table types the slot `int64` and the
CHECKER restricts the argument to the `os.Stdout`/`os.Stderr` selectors. No
program can name the fd, forge one, or observe that it is an integer. When `io`
lands these become `*os.File`; the spelling at every call site is already Go's.

**GAP 3 took the rename, not Go's architecture, deliberately.** `go test` on
package main compiles the package as a library and puts its testmain in a
SEPARATE package, so the program's main is compiled but never called. Renaming
reaches the same OBSERVABLE result — verified: a package whose main prints `42`
outputs only `ok` under `goo test`. The package-architecture change stays the
more faithful option and is the right move if `package foo_test` isolation is
ever wanted.

**GAP 1 went in at ZERO conflict delta**, tripwire checked three times (clean,
after two arms, after all seven) so any delta would have landed on a specific
arm. All seven combinations, because each is a distinct token sequence and a
partial fix leaves the same class of bug. The matrix row `stmt_for_forms`
claimed "3 forms" and passed continuously while five legal Go spellings were
parse errors — it tested the forms someone thought to write, not the forms the
spec permits. Hence a NEW row rather than an edit.

## GAP 5: calling `main()` emitted verifier noise — FIXED in PR #232 (unmerged)

```go
func helper() { main() }
func main()   { fmt.Println("hi") }
```
```
Module verification failed: Incorrect number of arguments passed to called function!
  %call = call i32 @main()
```

An ORDINARY `goo build`, no test mode involved — verified with a control run, so
GAP 3's rename neither causes nor worsens it. Codegen gives the entry an `i32`
return that no call site expects, and nothing rejects the call earlier.

It matters beyond its own shape: the golden-reject harness enforces a
project-wide rule that no LLVM verifier noise reaches users, and no fixture
covers this path. Severity low in practice, but the diagnostic is the worst
kind. Support it or reject it by name — do not fail in the backend.

## `goo test` (PR #227) — the 7-task arc, MERGED

`goo test [dir]` (default `.`) compiles the directory as the entry package WITH
its `_test` files, discovers the tests, synthesizes an entry point, runs it, and
exits on the verdict. **The full surface is documented in `CLAUDE.md`'s
`goo test` section — that is the reference, not this file.**

Shape worth remembering: `_testmain.goo` is generated in memory and parsed as
ONE MORE FILE of the package (the operation PR #226 made ordinary), never
written to disk; `--emit-testmain` prints it. Each test reaches `testing.Run`
as a **value**, which is the load-bearing choice — the runtime owns the call
frame, so it can `longjmp` out of `t.Fatal`. A generated main calling each test
directly could record a failure but could not stop one.

**Two claims in the plan of record were wrong, both caught by reading the code
before implementing:**

1. A qualified type name parses as ONE `BasicTypeNode` carrying a `package`
   field, NOT a selector expression over an identifier (`parser.y`'s
   `identifier DOT identifier` arm of `type_name`). The plan said to match
   `AST_SELECTOR_EXPR`, which would have rejected every valid test function.
2. The reject-fixture harness cannot express test mode — `run_golden_reject.sh`
   compiles in legacy mode, and discovery deliberately does not run for
   `goo build`, so a fixture there compiles clean and the suite reports a FALSE
   FAILURE. The case is a `cli_test` row instead; golden-reject stays 151.

**Discovery scans `_test` files ONLY.** That is Go's rule and a consistency
requirement: scanning an ordinary package file would reject a
`func TestHelper(x int)` that `goo build` accepts, so the same source would
compile or fail depending on the subcommand.

**`ProgramNode.package_name` was never written** (fixed, `495bd02`). The
`program:` action built the node and dropped `$1` on the floor, so the field was
declared and documented in `ast.h` yet permanently NULL, and the
`PackageDeclNode` leaked on every parse. Caught because `--emit-testmain`
printed `package main` for a `package testpkg` directory. ACTION-ONLY parser
change, so the LALR tables cannot move; tripwire 31/0 before and after.

**The conformance runner gained a `test` mode.** It compiled one `.goo` per row
in legacy mode and could not express `goo test` at all. A row written against
the old modes would have compiled a single file with a hand-written main —
testing the shim while its note claimed to cover discovery and synthesis, which
is exactly the silent rot the runner's own header exists to prevent. A
`test`-mode fixture is a DIRECTORY, `tests/spec/<id>/`.

## Stdlib arc (PR #229) — first tests, `strings.Builder`, `sort`

`goostd/` held 11 packages and **zero** test files. It now has three test files
and two new packages; surface 128 -> 159 symbols.

**The coverage gate was inverting its own incentive.**
`check_stdlib_coverage.sh` counted a symbol as covered only if it appeared in a
GOLDEN fixture, so a function exercised by a real test asserting a return value
per case was still reported UNCOVERED — pushing authors to write a second,
weaker proof (a fixture asserting one stdout line) purely to pass the gate. It
now reads two sources: goldens, and the `_test` files of goostd packages.

Two asymmetries in that matcher, both deliberate:

- A goostd symbol also accepts the BARE `Name(` spelling, but ONLY inside that
  package's own test files (an internal test calls `HasPrefix(...)`, never
  `strings.HasPrefix(...)`). Accepting a bare name globally would let an
  unrelated fixture's local `Index()` helper mask a real gap — verified by
  putting the call in a DIFFERENT package's test file and confirming it is
  still reported missing.
- A METHOD needs no such exception: it is always called through a receiver.

**The extractor never saw receiver methods** (fixed). `^func [A-Z]` cannot match
`func (l *Lane) Own()`. The script's own note called extending it YAGNI "for one
package" and listed six ungated `Lane` methods — there are **eight**
(`AllReduceSum`/`AllReduceMax` came later and never reached the comment). All
eight were golden-covered already, so extraction converted eight unverified
claims into eight checked ones at zero fixture cost. Adding a goostd TYPE with
methods is exactly the shape the gate was blindest to.

`sort` is heapsort over `Interface`. **`sort.Slice` is NOT provided and no
Goo-specific replacement was invented** — Go implements it with reflection,
which Goo lacks; the `Interface` form is the non-reflection path Go's own
`sort.Sort` requires anyway. Not stable, which is also Go's guarantee for
`sort.Sort`.

**Method worth reusing.** All 11 sort tests passed on the FIRST run, which for a
hand-written heapsort is weak evidence — the small cases fit in a heap too
shallow to expose a sift-down bug. What established correctness was a
20-element byte-for-byte differential against `go test` output, plus mutating
the child-selection comparison to watch four assertions fail.

## Spike: `errors.Is` / `errors.As` (done, NOT implemented)

**`errors.Is` — PROCEED, fully spec'd.** Every primitive already works, verified
end to end:

- An error value is a `goo_error_t*` (heap pointer, `{message, code, cause}`),
  so `==` is IDENTITY — exactly Go's sentinel semantics. Two `errors.New` calls
  with the same text compare false.
- `fmt.Errorf("%w")` genuinely wraps; chains nest and terminate at nil, and
  `errors.Unwrap(wrapped) == base` is true.

So `Is` is a loop, about five lines of C in the runtime. **It must be a C shim
row beside `Unwrap`** — a mixed shim+vendored package is IMPOSSIBLE: `errors`
is in `is_stdlib_shim_import`, so the import seeds the shim and never consults
`goostd/errors/` (verified: "Package 'errors' has no member 'Is'"). Four touch
points: a new `PARAMS_ERROR_ERROR` kind, a `SHIM_TABLE` row returning
`SHIM_RET_BOOL`, the runtime function, and a codegen intercept mirroring
`Unwrap`'s at `call_codegen.c:1904`. Go's `Is(error) bool` customization hook is
unreachable for the same reason `As` is — document that, do not silently omit
it.

**`errors.As` — OUT OF SCOPE, and vacuous rather than merely hard.** `error` is
a CONCRETE type in Goo, not an interface: every error is one `goo_error_t*`.
`As` exists to recover a specific concrete type from a chain, and there are none
to recover. This is a DELIBERATE, ALREADY-PINNED v1 decision —
`tests/golden/reject/custom_error_type_reject.goo` ("custom error types are not
supported in v1"), from P2-errors-a FIX F2, where returning a user struct in an
error slot reached codegen unchecked and SIGSEGV'd (exit 139) on three routes.
**No ADR is needed; the decision already exists.** Note that user-defined
INTERFACES with `Error() string` work fine and dispatch correctly — it is
specifically the builtin `error` that is concrete.

## PR #226 — the package is the compilation unit (multi-file packages)

**The scope changed from correctness burndown to capability.** Goo could not
compile a package of more than one file — not an imported package, and not
`package main`. Every program ever written in Goo was one file per package.

`resolve_package_dir` had always been N-file correct (glob, exclude tests,
qsort). The limit was downstream: `concat_package_sources` joined the files into
one buffer, and `parser.y`'s `program` rule admits exactly ONE package clause, so
a 2-file package became `package p … package p …` and died on the second clause.
Nobody had hit it because all 11 goostd packages were single-file — `strings.go`
555 lines, `lanes.go` 1032, both already straining against a ceiling no user
could reach.

Six commits: RED fixture → one file predicate shared by imports and the entry
package → parse each file separately (concat deleted) → per-file import scoping →
directory entry package (`goo build .`) → split `goostd/strings` in two for
permanence.

**Three defects the plan did not predict, all found by checking rather than
assuming:**

1. **Codegen needed the same pass ordering as the checker.** Restructuring
   `type_check_package` so each pass covers all files made type-checking correct,
   and then codegen failed with `Undefined identifier 'Bang'`.
   `codegen_generate_program` runs its forward-reference pre-pass over the one
   program it is handed, so emitting a.go fully before b.go left a.go's bodies
   looking for a prototype b.go had not created. Hoisted
   `codegen_predeclare_functions` across the package (idempotent — it guards on
   `LLVMGetNamedFunction`). The same fix was needed a second time for the entry
   package in commit 4.
2. **The filename lifetime was a use-after-free I introduced.** `parse_input`
   stamps the filename it is given into every `Position` BY POINTER. Passing
   `ps.files[fi]` meant `package_source_free` freed every string the package's
   diagnostics point at — it rendered as `Type error at @wI':6:2:`. The old code
   was safe by accident (it passed `import_path`, owned by main's AST). Paths are
   now owned by `PkgEntry` and transferred to the `Package` WITH the ASTs, since
   a comptime template's positions can still be reported during main's
   monomorphization.
3. **`ast_node_free` recurses into `->next`**, so per-file PROGRAM roots are held
   in an ARRAY and never chained — chaining would make one free reach all of them
   and turn each per-element teardown into a double free.

**A negative result worth keeping.** Commit 3 first re-seeded the import union
into the package scope for codegen, reasoning that codegen re-enters the checker.
Measured with it disabled: a package function calling `fmt.Println` compiles and
runs, `pkg_shim_share_probe` passes, `far-halo-probe` passes. A package-qualified
selector resolves through `stdlib_package_lookup` by NAME at codegen time, not
through the scope chain. The re-seed was deleted; the measurement is recorded
where it would have been. **Codegen does not need checker scopes for package
selectors** — worth knowing before anyone adds scope plumbing for codegen again.

**Diagnostic fidelity is why concat was deleted rather than repaired.** An error
in the second file reported `./multifile:21:8` — the import path as a filename,
and a concat-relative line (a.go's 15 lines + 1 join newline + b.go's line 5).
It now reports `.../twofile/bbb.go:6:2`. Pinned by a reject fixture whose sidecar
asserts filename AND line:column together, so a regression in either fails.

**Correction to a claim carried in the arc plan:** interface embedding is NOT
blocked and does NOT gate `io.ReadWriter`. Interface-in-interface works today —
`examples/iface_variadic_probe.goo` (merged in #225) uses it. What
`type_checker.c:5547` rejects is an interface embedded in a STRUCT
(`type T struct { io.Reader }`), a different and smaller gap. The stdlib figure
in that plan was also stale: 118 symbols, not 77 (`check-stdlib-coverage` prints
it every run).

2. Stdlib breadth: `sort`, `strings.Builder`, `bytes`, `io`, `errors.Is/As`,
