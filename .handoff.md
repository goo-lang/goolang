## FOUR INSTRUMENT DEFECTS, and every one produced plausible output

Two of them reported all-green. This is the session's most transferable lesson:
**check the input, not the output.**

1. **`git checkout --` silently no-oped on an UNTRACKED file**, and `2>/dev/null`
   hid the error, so mutations became CUMULATIVE. All six conditions reported
   CAUGHT with row counts climbing 2/9/10/12/12/12 — monotonic BECAUSE each run
   carried the previous deletions. Honest counts: 2/7/1/2/1/1, and two conditions
   were genuinely unguarded.
2. **An extractor returned EMPTY for `case AST_X: {`**, and the emptiness test then
   called 15 of 20 statement arms no-ops, `AST_RETURN_STMT` among them. Harmless
   for years under one test's polarity; catastrophic the moment a test asked "is
   this empty?".
3. **A self-test control asserted something false about the code.** `block_escape`
   runs two passes, so `walk_stmt`'s `AST_ARENA_BLOCK` arm only ever sees a NESTED
   block. The control was wrong, not the harness.
4. **`escape_arm_coverage.sh` DESTROYED UNCOMMITTED WORK.** Its clean-engine guard
   called `die`, which fired the EXIT trap, which ran `git checkout --` and deleted
   the very edit the guard objected to. Fixed: `restore_engine` refuses to act
   unless an injection landed.

Also: `tee | head` truncated a saved matrix to 5 of 17 rows via SIGPIPE, and zsh
does not word-split an unquoted `$OBJS`.

**A FIFTH, found in #264: valgrind is BLIND to half of the substring hazard.**
Measured by making `binding_is_owned` accept `AST_SLICE_INDEX_EXPR`:

- `low=1` -- `interior - 16` lands in the REAL header, reads refcount 0, and
  `goo_release` panics. Exit 2, and the rc check catches it.
- `low=32` -- it lands in the PAYLOAD, reads a large non-zero count, so the
  underflow panic never fires and the count never reaches 0. The atomic
  `fetch_sub` then WRITES a decrement into the middle of the string and returns.
  No `free()`, NO VALGRIND ERROR, exit 0 -- SILENT CORRUPTION of eight bytes.

So the runtime's refcount-0 panic is an ACCIDENTAL defence whose reach depends on
the offset, and it must never be relied on. `examples/arc_release_substring_probe
.goo` therefore prints its string, and the gate diffs that output against the
`GOO_ARC_RELEASE=0` control. A valgrind-only check had no teeth against half of
its own subject.

**A LIVE BUG, and the plan that found it was looking somewhere else (#265).**
While planning the switch cliff, reading `codegen_alloc_local_promoted` showed
that an ordinary local gets an ENTRY-BLOCK alloca while its initialising store
stays at the declaration site. So a local declared in a conditional block has a
slot on every path and a VALUE only on the taken one, and an LLVM alloca is undef.
Measured on `if c { a := new(int) }` with c false:

    Use of uninitialised value of size 8
       at goo_release (runtime.c:203)      <- the immortal-count read
     Uninitialised value was created by a stack allocation at f

and again at runtime.c:215, the `__atomic_fetch_sub` -- a WRITE through the
garbage pointer to an arbitrary address. **The program still exited 0.** Only
valgrind saw it. Reachable through a plain `if` since #261, unnoticed for four
increments, and found by reading code rather than by any test.

**AND THE PROBE FOR IT WAS VACUOUS ON THE FIRST DRAFT.** `sink = sink + *alive`
tripped the `AST_UNARY_EXPR` arm, marked `alive` escaping, and released NOTHING --
the probe passed while measuring nothing. Caught by checking the `[arc]` debug
line, not by review. `examples/arc_release_probe.goo` already records that arm as
the reason it increments a counter; the lesson did not transfer until it was
measured again.

## The design, for whoever picks this up

**Four conditions, all of which must hold** (`include/release_decision.h`):

1. `local_escape` says the value does not outlive the function.
2. The local OWNS the value, decided at the BINDING SITE.
3. Not declared inside `arena { }` (an arena pointer has no header).
4. Bound ONCE at function scope — not in a loop, and not re-assigned.

**The soundness direction is INVERTED from the escape passes.** There
`escapes = true` is safe. Here `release = false` is safe, so every unrecognised
path refuses and records WHY. `ReleaseVerdict` carries the cause, and every row
asserts the cause rather than a bare boolean.

**Condition 2 is a binding-site table, NOT ADR 0004's origin-emptiness.** That
proposal is constant-false: `local_escape`'s slots ARE local indices and a local
keeps its own bit for life, so no local's taint is ever empty. Measured in #259.
The working rule: `new(T)`/`&T{}` and composite literals are owned, a Goo call is
owned iff its callee's `return_escapes` is false, a shim call iff `non_retaining`
is 1, and a slice/index/selector or bare identifier is NOT owned.

**`ArcReleaseSite.field` says WHICH part of a slot is the object.** `-1` is the
slot's contents (a bare pointer, and a map, whose LLVM form is already `i8*`).
`0` is a fat value's buffer, and only `TYPE_SLICE` uses it.
**`TYPE_INTERFACE` is `{ vtable*, data* }` — field 0 there is the VTABLE, so there
is no general "release field 0" rule and never can be.**

**Ordering is STRUCTURAL.** `codegen_emit_deferred_calls` is a wrapper that runs
defers then releases, because a Go defer runs before the return and can read a
local through a closure. The 8 exit paths cannot drift.

**The release list is captured at DECLARATION time**, in `vscope_add`. Reading the
value table at exit emitted NOTHING — the function body is a block statement, so
`vscope_exit` truncates its locals first.

**`GOO_ARC_RELEASE=0` is the kill switch.** It leaves the plan NULL and emits
nothing. Every probe and `arena_rss_probe.sh` uses it as the control.

## NEXT, in the order I would take it

1. **THE ENTRY-BLOCK ZERO STORE.** The single largest bounded precision item
   left. Condition 5 (#265) refuses every local declared in a conditional block,
   and after #266 that includes each `switch`/`select`/`if let` case body — so
   the four arms widened which FUNCTIONS are readable, not which of their locals
   release. Store NULL into every released slot in the entry block, exactly as
   `defer_entry_store_zero` already does for a defer in a never-taken branch,
   then relax condition 5 to cover only what the store does not reach.
   `goo_release` no-ops on NULL, so an unexecuted declaration becomes harmless.
   Bounded, well-precedented, and it turns a refusal into reclamation.
2. **`escape_core`'s select arm marks EVERY local escaping** — it walks
   `sc->comm`, an EXPRESSION, into a `default:` that calls `escape_mark_all`.
   Found in #266 and left alone because the arm is shared by all three passes.
   Row 32 is the tripwire. Fixing it also makes the select rebind rule
   observable for the first time.
3. **The `AST_UNARY_EXPR` arm treats `*p` like `&x`** — it returns the operand's
   taint for every unary operator, so `return *p` marks `p` escaping though the
   deref copies the pointee out. It has now cost TWO probe drafts in one session
   (arc_release_cond_probe and arc_release_switch_probe both had to avoid it).
   Fixing it changes the arm all three passes share, so re-run the arm matrices.
4. **Transitive release** is where the rest of the daemon is, and it is a genuinely
   larger design: the map holds 20.3%, and a released `[]string`'s element strings
   are another 8.6%.

## Ledger — open, each with a reason

| Item | Why not yet |
|---|---|
| `param_escape`/`block_escape` lack the five statement rows | The rows for `MULTI_ASSIGN`, `switch`, `type switch`, `select` and `if` went into `local`, the pass T4 consumes. Both other suites are still GAP |
| Six statement arms uncovered in `local` | `IF_LET`, `CONST_DECL`, `UNSAFE`, `ASSERT`, `ASSUME` have 0 reach in every suite. `DEFER_STMT` is reached only in block, and it is entangled with `defer_is_like_go` and T4's release-versus-defer ordering, so a row should follow that decision rather than lead it |
| Five expression arms never reached | `SLICE_INDEX_EXPR`, `ARRAY_LITERAL`, `KEYED_ELEMENT`, `SLICE_CONVERSION`, `TYPE_ASSERT`. Whether the cause is "no fixture" or "the front end never builds this node" is UNDETERMINED, and guessing either way would be a false finding |
| `AST_POSTFIX_EXPR` has no soundness coverage | NOT a hole for the common shape: in Go `i++` is a statement, and the expression-statement arm frees the taint WITHOUT marking, so under-marking it is unobservable. Only an operand with taint or side effects (`arr[f(p)]++`) makes it observable |
| A map READ marks its key escaping | Over-conservative, pinned deliberately as local row 22. `goo_map_get` stores nothing, so only the base needs marking. MEASURED reason to leave it: the daemon's string local escapes through a map WRITE, so tightening the read rule reclaims ~0% |
| `append`'s ELEMENTS still escape | Correct, not a gap: the buffer keeps a copy of each, so a pointer element genuinely outlives the call. It is why a `[]string`'s element strings are not reclaimed |
| Map keys/values untracked at runtime | `goo_map_set_sv` keeps the key pointer verbatim and never frees. 20.3% of the daemon, and unreachable by any codegen-side release |
| Named results are NOT in `LocalEnv` | Unchanged. Still the only sink covering `p = q; return` with a named result. Pinned by param_escape row 20 |
| Method summaries resolve by BARE name | Unchanged. `registry_find` returns the first match |
| `s += "x"` on a string is refused | Condition 4 counts it as a second binding -> RELEASE_NO_REBOUND. A release of the LAST value would in fact be correct, because every concatenation returns fresh memory. Relaxing condition 4 is a separate change with its own rows. Pinned by row 24 |
| A NAMED string or slice type is refused | `type Name string` has kind TYPE_NAMED, so codegen_arc_note_local's shape test fails. Lost reclamation, never an unsafe free |
| An integer `+` reads RELEASE_OK | Deliberate, and pinned by row 25. release_decision is pure AST with no type information, so it cannot tell a string `+` from an integer one. Costs nothing: the codegen layer refuses a bare i64 slot. Do NOT narrow the arm -- the two-layer split is what keeps each layer simple |
| A local declared in ANY conditional block is refused | Condition 5 (#265). The slot is hoisted to the entry block, the store is not, so an unexecuted declaration leaves undef. An ENTRY-BLOCK ZERO STORE would lift this and recover the precision, in the shape `defer_entry_store_zero` already uses. This is the single largest precision item left, and it is a bounded codegen change |
| `escape_core`'s select arm marks EVERY local escaping | Found in #266, NOT fixed. Its `AST_SELECT_STMT` arm calls `escape_walk_stmt` on `sc->comm`, but the grammar makes comm an EXPRESSION, so it lands on a `default:` that calls `escape_mark_all`. A precision bug, not a soundness one. The arm is shared by all three escape passes, so a fix means re-running three arm matrices. Row 32 is the TRIPWIRE: it must become RELEASE_NO_REBOUND when this is fixed |
| `select`'s `is_declare == 0` rebind rule is unobservable | Consequence of the row above: condition 1 refuses first. The rule IS correct -- bypassing condition 1 makes row 32 read REBOUND -- but no verdict row can pin it today |
| `assert`, `assume`, `asm`, label and `goto` stay unread | They keep RELEASE_NO_UNKNOWN reachable, which the teeth script needs. A label WRAPS a statement, so refusing on one is conservative for a real cause. Row 34 is the only row holding that verdict |
| Cycles | ADR 0002 names this as the real cost with no cheap fix |
| `interface == interface` fails codegen | Pre-existing, untouched |
| `types.c:603-607` frees interface methods as an ARRAY | Latent, pre-existing |
| `ownership_checker.c` compiles into `bin/goo` with ZERO call sites | Unchanged |

## The direction, stated plainly

Last session's close-out said "nothing this session freed a single byte". This one
freed 115.8 MB on the benchmark that motivated ADR 0002, and the way it got there
was refusing to trust a projection. Five plans were invalidated by a measurement
that cost seconds, and four instruments were caught lying before their output was
believed.

`TYPE_STRING` shipped in #264, then #265 and #266 closed the switch cliff — and
between them they produced this session's sharpest lesson. The plan for #266 was
"add recursion plus rows". Reading the codegen first found a LIVE use-of-undef bug
that had been reachable through a plain `if` since #261, and that bug had to ship
FIRST because the four arms would have multiplied its reach. A plan that had gone
straight to the feature would have widened a memory-corruption path.

Note what #266 did and did not buy: it widened which FUNCTIONS are readable, not
which of their locals release. Condition 5 still refuses every case-body local.
The entry-block zero store is what converts that refusal into reclamation, and it
is now the largest bounded item on the list.

The remaining bytes are in the map and in transitive release. Both are real
designs, not increments.
