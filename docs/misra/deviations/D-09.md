> Rule 21.8: The Standard Library functions `abort`, `exit`, `getenv` and
> `system` of `<stdlib.h>` shall not be used.

## Summary

The compiler's exit status is its contract with the build system, and `exit` is
how it is set. `getenv` reads `GOOROOT` and the debug switches
(`GOO_ARC_RELEASE`, `GOO_ARC_DEBUG`). `abort` is how an assertion failure ends
the process. `system` survives in one place only: the Windows linker path.

Baseline: 14 reports in hand-written code, in `src/compiler/goo.c`,
`src/runtime/runtime.c` and `src/runtime/deadlock.c`.

**The baseline undercounts.** The `system` call at `src/codegen/codegen.c:1797`
sits inside `#ifdef _WIN32`, so the Linux scan never preprocessed it. Any
guideline whose only violations are in a platform-conditional branch will read
as clean on this platform. That is a property of the scan, not of the code.

## Detailed description

MISRA's rationale differs per function, and so does the answer.

**`exit`.** The objection is that it does not return, so the calling function's
remaining code and its callers' cleanup never run. For a compiler this is the
intended behaviour: a fatal diagnostic ends the run, and the operating system
reclaims the process. The exit status is the only signal a build system reads.

**`abort`.** The objection is that it terminates without flushing streams or
running `atexit` handlers. It is reached from `include/goo_assert.h` and
`include/ergonomic_errors.h`, on assertion failure — the situation in which
continuing is not an option and cleanup code cannot be trusted to run. Note
that the allocation wrappers in `xalloc.h` use `exit(1)` rather than `abort`,
so an out-of-memory failure does flush.

**`getenv`.** The objection is that the environment is implementation-defined
and the returned pointer may be invalidated by a later call. Both are true.
`GOOROOT` resolution and the debug switches are read once, early, and copied.
This is a hosted command-line tool whose configuration comes from the
environment by design.

**`system`.** The objection is that it hands a string to a command interpreter.
This is a genuine injection hazard, and the project has already acted on it: the
POSIX link path was changed to `fork()` + `execvp()` on an argv vector under
P3.11, precisely because `system()` shells the command through `/bin/sh`, which
forced a fixed 2048-byte buffer and word-split any unquoted path component. An
output path containing a space silently linked into three garbage argv words.

**Four `system()` calls remain.** An earlier draft of this record said there was
one. That was wrong, and it was wrong because the grep that produced it was
truncated with `head -5`. The full list:

| Site | Linked into `bin/goo`? | Argument | Assessment |
|---|---|---|---|
| `src/codegen/codegen.c:1797` | **yes** | `snprintf`-built link command | Windows-only branch. Carries the fixed 2,048-byte buffer and the path-with-a-space defect that P3.11 removed from the POSIX path. |
| ~~`src/types/proof_obligations.c:243`~~ | no | ~~`"mkdir -p %s"` with a caller-supplied `cache_dir`~~ | **FIXED 2026-08-14.** Was a shell injection: a `cache_dir` containing `;` or `$(...)` ran arbitrary commands, and the 512-byte buffer truncated silently. Three of the four are in the Task #22-era framework code that P5.6 unlinked, so
they are not reachable in the shipped compiler. That bounds the severity. It
does not make them acceptable: the code is still in the tree, still compiles
under the standalone test targets, and would become live the moment anything
re-links it.

## Justification

- **Return a status up the call chain instead of calling `exit`.** This is the
  clean form and it is right for a library. It is wrong for `main`'s immediate
  vicinity, where the status has arrived at its destination. The tree already
  returns statuses through the compilation pipeline; the `exit` calls are at the
  edge.
- **Replace `abort` with a longjmp to a top-level handler.** Rejected. An
  out-of-memory abort is the one case where unwinding through arbitrary code is
  least likely to work, and Rule 21.4 already covers `setjmp` (see D-10).
- **Replace `getenv` with a configuration file.** Rejected as worse: it adds a
  file format, a parser and a search path to avoid a documented interface.

## Conditions under which the deviation is requested

- `exit` in `src/compiler/goo.c`, the `xalloc.h` allocation wrappers and the
  runtime's fatal paths, to set the process exit status
- `abort` in `include/goo_assert.h` and `include/ergonomic_errors.h`, on
  assertion failure
- `getenv` for `GOOROOT` and the `GOO_*` debug switches, read once and copied

`system` is **excluded**. All four existing calls are **known defects**, not
deviations, and they are listed as actions below. Introducing a new `system`
call anywhere is a violation.

## Consequences of non-compliance

`exit` and `abort` skip cleanup. In a process that is ending anyway, the
operating system reclaims memory and file descriptors, and the risk is limited
to a buffered stream that is not flushed. `abort` in particular loses buffered
diagnostic output, which can make an out-of-memory failure less informative than
it should be. The allocation wrappers write their message to `stderr`, which is
unbuffered by default, so the message itself survives.

`getenv` returning a pointer that a later `setenv` invalidates is avoided by
copying at the point of read. Whether every site copies has not been verified,
and doing so is a small, worthwhile check.

## Actions to control reporting

Suppressed project-wide, naming this record:

    --suppress=misra-c2012-21.8   # deviation D-09

Four actions, in severity order:

1. ~~**Fix `proof_obligations.c:243`.**~~ **DONE 2026-08-14.** Replaced
   `system("mkdir -p %s")` with `mkdir(2)`. One deliberate narrowing: `mkdir(2)`
   does not create parent directories, and the sole caller passes a one-level
   path under `/tmp`. `scripts/proof_cache_shell_probe.sh` now gates it, and it
   is in `verify-core`. The probe is two-sided: it asserts the benign path still
   creates the directory, so it cannot pass by the function doing nothing.
2. **Fix the Windows `system()` call** at `codegen.c:1797`. It is the only one
   in shipped code. The Windows equivalent of the P3.11 fix is `CreateProcess`
   on an argv vector, or `_spawnvp`. Until it lands, a Windows build fails to
   link any output path containing a space.
3. **Replace or delete the two `ipfs_client.c` calls.** `posix_spawn` on an argv
   vector for the daemon; a recorded PID and `kill(2)` instead of `pkill ipfs`,
   which currently kills processes this code never started.
4. **Add a grep gate** to `make verify-core` that fails on any `system(` call
   not on the known list, since `system` is excluded from this deviation and the
   project-wide Rule 21.8 suppression would otherwise hide a new one. The gate
   must scan the **source text**, not the preprocessed translation unit: the
   Linux scan missed `codegen.c:1797` entirely because it sits behind
   `#ifdef _WIN32`.
