> Rule 11.3: A cast shall not be performed between a pointer to object type and
> a pointer to a different object type.

## Summary

The AST is a tagged single-inheritance hierarchy in the standard C idiom: every
node type embeds a common `ASTNode base` as its first member and carries a kind
tag. Every consumer of the AST — the type checker, the escape analysis, codegen,
the printer, `ast_node_free` — downcasts from `ASTNode *` to the concrete node
type after switching on that tag. Rule 11.3 forbids the cast that makes this
representation work.

Baseline: 912 reports in hand-written code, plus 279 in bison-generated code.

## Detailed description

`include/ast.h` declares one opaque base and a concrete struct per node kind:

```c
typedef struct ASTNode ASTNode;

typedef struct {
    ASTNode base;
    char* package_name;
    struct ASTNode* imports;
    struct ASTNode* decls;
} ProgramNode;
```

Consumers follow the same shape everywhere:

```c
case AST_DEFER_STMT: {
    DeferStmtNode* s = (DeferStmtNode*)node;
    ast_node_free(s->call);
    break;
}
```

The cast is well defined. C guarantees that a pointer to a structure, suitably
converted, points to its initial member and vice versa, so a `ProgramNode *`
converted to `ASTNode *` and back yields the original pointer with correct
alignment. The tag in `base` is what makes the downcast sound: the `switch`
that selects the case has already established which concrete type the object
has.

MISRA's rationale for Rule 11.3 is that a cast to a differently-typed pointer
can produce a pointer that is incorrectly aligned for the destination type, and
can invite an access that violates the effective type of the object. Neither
follows here, because the destination type's first member *is* the source type.

## Justification

The alternatives all cost more than the rule saves.

- **A tagged union of all node types.** This is the closest MISRA-clean
  representation. It removes the cast, but makes every node the size of the
  largest variant. The AST is the dominant allocation in the compiler, and node
  sizes differ by an order of magnitude, so this trades a well-defined cast for
  a large and permanent memory regression. It would also require touching every
  node construction and access site in the tree.
- **A union of pointers inside the base.** Removes the cast at the price of an
  extra indirection on the hottest data structure in the compiler, and an extra
  allocation per node.
- **Accessor functions per node type.** Hides the cast inside a function rather
  than removing it. The cast still occurs and the rule is still violated; the
  tool simply stops reporting it at 912 sites and reports it at 60 instead.
  Rejected as concealment rather than compliance.
- **Rewriting the AST in a language with sum types.** Out of scope.

## Conditions under which the deviation is requested

Casts between `ASTNode *` and a concrete AST node type, in either direction,
where the concrete type embeds `ASTNode base` as its first member and the cast
is guarded by a check of the node's kind tag.

The same reasoning extends to the parallel hierarchies that use the same idiom.
It does **not** extend to arbitrary pointer casts. A cast between two unrelated
object types remains a defect, and this deviation is not a licence for one.

## Consequences of non-compliance

The risk this deviation accepts is a downcast to the wrong concrete type: a
`switch` case that casts to a type the tag does not name. That is a real defect
class and it has bitten this project. The comment at `src/ast/ast.c:343` records
a case the parser fuzzer found on 2026-08-08, where a node reached `default:`
and its wrapped expression was never freed.

Verification that covers this risk, all of which already runs:

- `bin/fuzz_parse`, which is what found the 2026-08-08 defect
- `ast-free-leak-probe` and `ast-free-census`
- valgrind and AddressSanitizer gates, which turn a wrong downcast into a
  reported invalid read rather than silent corruption

The gap worth naming: nothing statically checks that the cast in a `case` matches
the tag that selects it. That check is possible — a script could compare each
`case AST_X:` against the type named in the cast on the following lines — and it
would be a better use of effort than complying with Rule 11.3.
