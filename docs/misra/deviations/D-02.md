# D-02 — Rule 17.7, discarding a function's return value

| | | | |
|---|---|---|---|
| **Project** | goolang | **Deviation ID** | D-02 |

| **Source** | cppcheck 2.21.1 MISRA addon | **Scope** | Project, limited |

> Rule 17.7: The value returned by a function having non-void return type shall
> be used.

## Summary

This is the one deviation in this set that is **partial**. Rule 17.7 covers two
very different situations that the tool reports identically, and only one of
them is safe to waive.

- Discarding the result of `printf`, `fprintf`, `snprintf` and `puts` is
  harmless and universal. Waived.
- Discarding the result of `pthread_mutex_lock`, `pthread_cond_init`, `fclose`
  or any function whose result reports whether the operation happened is a
  defect. **Not waived.** It goes on the Phase 1 backlog.

Baseline: 3,225 reports in hand-written code. Measured 2026-08-14 with
`tools/split_17_7.py`, which resolves each report's column to the discarded
callee:

| | Count |
|---|---|
| Waived by this record | 1,709 |
| **Kept — violations to fix** | **1,516** |

The kept half is dominated by exactly what the rule is for:

| Callee | Kept | Callee | Kept |
|---|---|---|---|
| `pthread_mutex_unlock` | 411 | `clock_gettime` | 45 |
| `pthread_mutex_lock` | 264 | `pthread_cond_broadcast` | 40 |
| `pthread_mutex_destroy` | 85 | `sprintf` | 18 |
| `repl_printf` | 75 | `fclose` | 16 |

840 of the 1,516 are an unchecked `pthread_*` return value. That is the single
largest concrete defect class the whole scan found.

## Detailed description

MISRA's rationale is that a function returns a value for a reason, and
discarding it usually means an error path is not being taken. Directive 4.7
states the same idea from the other side: if a function returns error
information, that information shall be tested.

The rationale is correct for the second group above. `pthread_mutex_lock` can
fail with `EDEADLK` or `EINVAL`. A caller that ignores that and proceeds into
the critical section has a data race that no amount of testing will reliably
surface. The project's own memory-model work depends on this discipline holding.

It is not correct for the first group. The C standard specifies that `printf`
returns the number of characters written, or a negative value on error. There
is no useful recovery from a failed diagnostic write in a compiler: the
diagnostic channel is the only way to report the failure, and it is the thing
that failed. Every C program in existence discards these results, and requiring
`(void)` on each one adds 1,300 casts that carry no information.

The addon reports both groups as `misra-c2012-17.7`. It cannot tell them apart,
so the split has to be made by the project, not by the tool.

## Justification

- **Waive Rule 17.7 entirely.** Rejected. It would waive the
  `pthread_mutex_lock` case, which is a real concurrency defect class in a
  codebase with a documented interest in getting concurrency right.
- **Adopt Rule 17.7 entirely.** Rejected on cost, and because the resulting
  `(void)printf(...)` prefix on every diagnostic obscures rather than clarifies.
  MISRA itself notes that a cast to `void` is the accepted way to show the
  discard is deliberate, but "deliberate" is not in doubt for `printf`.
- **Split by callee, waive the harmless group.** Adopted. This is the only
  option that keeps the rule's value where the value is.

## Conditions under which the deviation is requested

The deviation permits discarding the return value of the following functions
only:

| Function | Reason |
|---|---|
| `printf`, `fprintf`, `vfprintf`, `vprintf` | diagnostic output; no recovery available |
| `snprintf`, `vsnprintf` | truncation is handled by sizing the buffer, not by the result |
| `puts`, `fputs`, `fputc`, `putchar`, `fflush` | as above |
| `memcpy`, `memmove`, `memset`, `strcpy`, `strcat`, `strncpy`, `strncat` | the result is the destination pointer the caller already holds |

This list is the `WAIVED` set in `tools/split_17_7.py`. Changing one must change
the other, and the split must be re-measured afterwards.

Every other function is out of scope. Discarding the result of a function not
on this list is a violation to be fixed, not deviated. Note that `sprintf` is
deliberately **absent** from the list: it can overflow, and its 18 sites are
Phase 1 work.

## Consequences of non-compliance

For the listed functions: a failed write to `stdout` or `stderr` goes
unreported. In practice this means a compiler run whose diagnostics were lost to
a closed pipe still exits with its normal status. The exit status is the
authoritative signal for a build system, so this does not cause a silent
success.

For everything else the rule remains in force, so this deviation adds no risk
there.

## Actions to control reporting

**The split is measured** (2026-08-14). Two actions remain:

1. **Suppress by callee, not project-wide.** cppcheck cannot suppress
   `misra-c2012-17.7` for a set of callees directly. The workable forms are an
   inline suppression at each waived call site, or — better — a wrapper macro
   for the diagnostic printers that carries the suppression once. Until one of
   these lands, the gate suppresses 17.7 project-wide, which also hides the
   1,516 real ones.
2. **Fix the 1,516** under Phase 1, starting with the 840 `pthread_*` returns.

The current suppression, and its cost, stated plainly:

    misra-c2012-17.7   # D-02 PARTIAL - also hides 1,516 real violations

This is the weakest entry in the suppression file. It is the only one that
hides violations the project intends to fix, and it should be narrowed or
removed as Phase 1 progresses. Re-measure with:

    python3 docs/misra/tools/split_17_7.py <scan-with-columns> .

The scan needs `{column}` in its template for that script to work.
