> Rule 17.1: The features of `<stdarg.h>` shall not be used.

## Summary

The diagnostic printers take a format string and a variable argument list, and
forward it to `vfprintf`. That requires `va_list`, `va_start`, `va_arg` and
`va_end`.

Baseline: 50 reports in hand-written code.

## Detailed description

MISRA's rationale is that `<stdarg.h>` has several undefined behaviours: calling
`va_arg` with a type that does not match the argument actually passed, calling
`va_start` without a matching `va_end`, and using a `va_list` after it has been
passed to a function that consumed it.

All three are real. The mitigating fact here is the shape of the use. The
project does not write code that inspects a variable argument list with
`va_arg`; it writes forwarding wrappers, which capture the list and hand it
straight to a `v`-suffixed standard function:

```c
void diag_error(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    vfprintf(stderr, fmt, ap);
    va_end(ap);
}
```

This pattern cannot commit the `va_arg` type-mismatch error, because it never
calls `va_arg`. The remaining risk is a format string that does not match its
arguments, which is the same risk as D-04 and is covered by the same
enforcement.

## Justification

- **Fixed-arity diagnostic functions.** One function per argument count and
  type combination. Rejected: it multiplies the diagnostic API by a large
  factor and moves the format-string risk to the call site unchanged.
- **Build the message with `snprintf` at each call site.** Moves the varargs use
  from one wrapper to every caller, which is strictly worse.
- **Deviate, limited to forwarding wrappers.** Adopted.

## Conditions under which the deviation is requested

Functions that capture a variable argument list with `va_start` and pass it
unmodified to a `v`-suffixed standard library function (`vfprintf`, `vsnprintf`,
`vprintf`), then release it with `va_end` on every exit path.

Direct use of `va_arg` to inspect the list is **excluded**. Adding a `va_arg`
call is a violation to be reviewed on its own terms, not something this
deviation covers.

## Consequences of non-compliance

A `va_start` without a matching `va_end`, or a return between them, is
undefined. Because the pattern is short and stereotyped, this is visible on
inspection.

Enforcement in place:

- `-Wformat` through `-Wall` checks the format string against the arguments at
  the call site for functions marked with the `format` attribute
- cppcheck's `va_end_missing` and `va_start_wrongParam` checks

Gap worth naming: the diagnostic wrappers should carry
`__attribute__((format(printf, N, N+1)))` so that `-Wformat` reaches their
callers. Whether every wrapper has it has not been checked, and doing so is a
cheap improvement with more value than complying with this rule.
