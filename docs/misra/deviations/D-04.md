> Rule 21.6: The Standard Library input/output functions shall not be used.

## Summary

A compiler reads source files and writes diagnostics and object files. Rule 21.6
forbids the entire mechanism by which it does so.

Baseline: 1,372 reports in hand-written code.

## Detailed description

MISRA's rationale is that `<stdio.h>` has unspecified, undefined and
implementation-defined behaviour in a number of places, and that a freestanding
implementation is not required to provide it at all. The second half is the
decisive one for MISRA's audience: an embedded target may have no file system
and no console, so code that assumes `printf` is not portable to it.

Neither concern transfers. `bin/goo` is a hosted program on a hosted
implementation. It is a command-line tool whose entire external interface is
files in, files and diagnostics out. Removing `<stdio.h>` would mean
reimplementing it on raw `write(2)`, which is the same functionality with more
of the project's own code between the compiler and the operating system.

The specific hazards MISRA lists are worth keeping in view even while deviating:

- `%n` in a format string is a security hazard. It does not appear in this tree
  (verified 2026-08-14 by grep over `src/` and `include/`).
- A format string that does not match its arguments is undefined. This is
  covered: `-Wall -Wextra` includes `-Wformat`, cppcheck's own
  `invalidPrintfArgType_*` checks are enabled, and the baseline scan reported
  several genuine mismatches in `src/concurrency/performance_monitoring.c` that
  are on the Phase 1 backlog.
- Reading with `%s` into a fixed buffer overflows. The tree uses `sscanf` at
  seven sites — two in `src/concurrency/numa_scheduling.c` and five in
  `src/ide/lsp_enhanced.c` — and every one of them reads `%d` into an `int`.
  There is no `%s` read anywhere (verified 2026-08-14). The hazard is therefore
  absent today, but nothing prevents it being introduced, which is why the
  actions below add a gate rather than relying on the current state.

## Justification

- **Reimplement I/O on POSIX `read`/`write`.** Achievable, and it would satisfy
  the letter of the rule. It replaces a heavily tested standard library with
  project code, and it does not remove the format-string hazard, because the
  formatting still has to happen somewhere. Rejected as a net loss.
- **Restrict to a small wrapper layer and deviate only there.** Attractive on
  paper: one file allowed to call `<stdio.h>`, everything else calling the
  wrapper. In practice the diagnostic printers already are that layer for most
  output, but the tree also writes object files, reads source, and drives LLVM's
  own file output. Reducing 1,372 sites to a genuinely small number is a
  refactor, not a policy decision, and it is not justified by the risk.
- **Deviate.** Adopted.

## Conditions under which the deviation is requested

All use of `<stdio.h>` in `src/` and `include/`, including the seven existing
`sscanf` calls that read `%d` into an `int`.

Two things are **excluded** from this deviation:

- the `%n` conversion specifier, in any function
- a `scanf`-family read into a character buffer (`%s`, `%[`) without a field
  width

Introducing either is a violation, not a deviation, and the actions below make
that enforceable.

## Consequences of non-compliance

The residual risk is a format string that does not match its arguments. The
compiler's own diagnostics are the most format-heavy code in the tree, and a
mismatch there is undefined behaviour on a path that only runs when something
has already gone wrong — which is the worst place for it.

Enforcement in place:

- `-Wformat` through `-Wall`, required clean by `make verify-core`
- cppcheck `invalidPrintfArgType_*`, enabled in the same run as the MISRA addon
- the Phase 1 backlog item for the mismatches the baseline scan already found

## Actions to control reporting

Suppressed project-wide, naming this record:

    --suppress=misra-c2012-21.6   # deviation D-04

Add a grep gate to `make verify-core` that fails on `%n` in any format string,
and on an unbounded `%s` or `%[` in a `scanf`-family call. Both are excluded
from this deviation, and the project-wide suppression above would otherwise
hide them.
